- [P0] [SlimWise: Decoupling Expert Pruning Across Prefill and Decode for Efficient MoE Serving](https://huggingface.co/papers/2609.34117)（Hugging Face Daily Papers · 论文 · 推理部署与性能优化 · 新 · 2026-10-07 · Gunho Park, Kyoungho Jeun, Juntaek Oh）
  - 中文摘要：这篇论文提出 SlimWise，一个面向 MoE 模型推理的服务框架。它观察到批量解码时几乎会触达整个专家池，导致专家权重搬运成为主要瓶颈，而传统专家剪枝会连计算密集的 prefill 阶段一起剪掉，损失质量却换不来吞吐。SlimWise 的做法是按推理阶段定制专家池：prefill 用完整模型，decode 用剪枝模型，并直接复用 prefill 生成的 KV cache 而不做转换，实现免训练的 KV cache 交接；同时引入低成本蒸馏阶段，让解码器从完整模型的 KV cache 继续生成，只更新少量参数。作者在 vLLM 中实现，支持 PD 分离与 PD 同机部署。
  - 亮点：按推理阶段解耦专家池，prefill 全量、decode 剪枝，并用免转换 KV cache 交接把精度损失压到很小。
  - 注意：摘要提到基准准确率会掩盖剪枝导致的生成长度变化，说明单看 accuracy 可能误判；另外该方法依赖 vLLM 与特定 MoE 结构，迁移到其他推理栈或稠密模型未必直接适用。
  - 学习指引：重点看三处：一是 prefill 与 decode 阶段专家激活模式的差异分析，这是方法动机的核心；二是 KV cache 免转换交接的具体实现，理解为什么剪枝后仍能复用完整模型的 cache；三是 vLLM 中的工程实现与 PD 分离/同机两种部署形态，以及蒸馏阶段只更新哪些参数。实验部分注意对比不同剪枝准则和两个 MoE 骨干下的精度-吞吐权衡。
  - 优先级依据：MoE 推理优化是当前大模型工程的高频考点，且该工作给出了可落地的系统方案，值得当天精读。

  - 中文摘要：论文提出 UNREAL，试图用单一模型内部机制统一语料级检索和长上下文推理两种证据选择场景。它直接从冻结 LLM 的内部表示中编码 chunk 并生成检索 query，只增加不到 50 万可训练参数，骨干模型完全不动。在 3B token、2100 万 chunk 的 Wikipedia 索引上，四个稠密与混合骨干都超过现有 retriever-reranker 系统，HotpotQA recall 从 49.1% 提到 73.2%，2WikiMultiHopQA 从 31.7% 提到 60.1%，MuSiQue 从 8.8% 提到 14.4%。同一选择机制用于长上下文任务时，能在生成前去掉干扰项，把 NoLiMa 在 128K 上下文下的准确率从 1.0% 提到 24.83%，LV-Eval F1 从 49.97% 提到 54.66%，并降低 FLOPs 和首 token 延迟。

  - 优先级依据：RAG 与长上下文的统一是重要方向，且该工作给出了大幅指标提升和低参数开销的清晰方案，值得当天重点看。

  - 中文摘要：论文提出 DAEDALUS，一种在没有现成任务和 oracle verifier 的情况下，从自生成练习中引导可复用 agent 记忆的方法。它让两个 agent 配合：explorer 与环境交互，生成有挑战但可解的任务；solver 尝试这些任务。每次 solver 失败会导出一条启发式规则，只有当 solver 在上下文中反复使用该规则并成功后才被接受，这些结果同时反馈给 explorer 调整后续任务难度。被接受的启发式规则最终整合成记忆库供测试时使用。在 AppWorld、τ^2-bench 和 AutomationBench 上，DAEDALUS 提升了平均成功率。

  - 优先级依据：Agent 记忆与自举学习是当前热点，且该工作去掉了对人工规则和 oracle 的依赖，方法设计有启发性，值得当天重点看。
- [P0] [Harness-Aware Distillation for Small Language Model Agents](https://huggingface.co/papers/2610.02858)（Hugging Face Daily Papers · 论文 · 后训练与对齐 · 新 · 2026-10-07 · Moonseok Choi, Taehong Moon, Giung Nam）
  - 中文摘要：论文关注语言模型 agent 部署时总带着 harness，即管理上下文、工具和反馈的外围软件。当把 agent 蒸馏到小模型时，harness 保持不变，学生模型真正需要的是 harness 无法提供的教师特有能力和正确利用 harness 信息的能力。标准蒸馏模仿教师全部输出，把 harness 当作输入的一部分。作者提出 Harness-Aware Distillation，把蒸馏聚焦在教师超出 harness 的增量上：一是 action preference，对比同一教师在有和没有 harness 信息时的动作，并在学生自身推理之后打分；二是 validity check，丢弃偏好动作与 harness 记录矛盾的偏好对。HAD 不需要任务奖励、成功标签或未来信息，在多个长程 agent benchmark 和模型上超过同 harness 的 on-policy 蒸馏基线。
  - 亮点：把 harness 从蒸馏输入中剥离出来，只蒸馏教师超出 harness 的增量能力，且不需要任务奖励或成功标签。
  - 注意：方法假设 harness 固定不变，若部署时 harness 版本或工具集变化，蒸馏出的偏好可能失效；validity check 依赖 harness 记录准确，记录有噪声时可能误删有效偏好对。
  - 学习指引：重点看 action preference 如何构造对比样本，以及为什么要在学生自身推理之后打分；validity check 如何利用 harness 记录过滤矛盾偏好对也值得细看。实验上关注与 on-policy 蒸馏基线的对比设置，以及在不同长程 agent benchmark 上的稳定性。
  - 优先级依据：小模型 agent 蒸馏是后训练中的实用方向，该工作对 harness 与模型能力的边界划分清晰，值得当天重点看。
- [P0] [JudgeMoE: Distributional Aggregation for LLM-as-a-Judge](https://arxiv.org/abs/2610.07109)（arXiv cs.CL · 论文 · 评测与安全 · 新 · 2026-10-07）
  - 中文摘要：这篇论文提出 JudgeMoE，一个轻量级聚合器，用于改进 LLM-as-a-Judge 的评分方式。传统做法将 LLM 裁判的分数分布压缩为单一标量，丢失了不确定性和分歧信息；JudgeMoE 则对缓存的裁判分数分布赋予样本级权重后再融合，并系统研究了分数范围选择、软评分与硬解码的差异。实验显示，在原始 10 格基准上，JudgeMoE 相比均匀对数池化将平均 Spearman 相关系数提升 0.079；扩展到 16 格后，相比最强局部单裁判平均提升 0.0393，12/16 格为正，单侧 Wilcoxon 符号秩检验 p=0.0091。
  - 亮点：将 LLM 裁判的分数分布而非标量作为聚合对象，用轻量 MoE 式权重融合，在多个基准上稳定提升与人类判断的相关性。
  - 注意：方法依赖已有裁判分数分布的缓存，且最优聚合策略随任务和裁判池变化，迁移到新场景时可能需要重新验证，不能直接套用固定配置。
  - 学习指引：重点看方法部分如何定义和缓存裁判分数分布、如何学习样本级聚合权重，以及实验中的协议研究（分数范围、软/硬评分）。同时关注验证分析中“最优聚合方法依赖任务和裁判池”的结论，这对实际搭建评测流水线很有参考价值。
  - 优先级依据：LLM-as-a-Judge 是评测方向的核心工程问题，该工作提供了可落地的聚合改进和统计验证，对学习评测系统设计有直接帮助。
