- [P0] [The Other Half of the Memory Wall: Serving 35B MoEs from SSD with Trained Routing Prediction](https://huggingface.co/papers/2609.18063)（Hugging Face Daily Papers · 论文 · 推理部署与性能优化 · 新 · 2026-09-17 · Yu Lin, Yiming Wang, Runyuan Cai）
  - 中文摘要：这篇论文提出 Edge0，一个面向消费级硬件的流式 MoE 推理引擎。核心问题是 35B 级 MoE 即使 4-bit 量化后权重仍有 19.5GB，单卡 24GB 机器无法常驻，而朴素 SSD offload 又因为第 N+1 层专家必须在第 N 层输出之后才能确定，无法提前预取。作者用一个 prerouter 逐层提前一个 token 预测下一层路由，并直接把预测当作真实路由使用，使预取的专家集合与最终路由集合一致；再用一个未合并的 recovery LoRA 补偿 int4 量化和路由替换带来的质量损失。最终在单张 24GB 机器上以 3GiB 峰值活跃内存跑到 20tok/s，五个公开基准上平均只比 fp16 教师低几个点，并开源了框架、checkpoint 和 adapter。
  - 亮点：把 MoE 路由预测直接当作路由使用，使预取集合与真实路由集合严格一致，从而让 SSD 读取真正被计算掩盖。
  - 注意：该方法依赖路由可预测性，若模型路由本身高度随机或任务分布与训练预测器差异大，预测误差会直接变成质量损失；此外 20tok/s 在交互式场景仍偏慢，且结论主要基于单张 24GB 消费卡，未覆盖多卡或数据中心 GPU 场景。
  - 学习指引：重点看三块：一是 prerouter 的设计与训练方式，理解它如何把“预测下一层路由”变成可提前执行的调度信号；二是 recovery LoRA 为什么选择 unmerged，以及它如何同时补偿量化误差和路由替换误差；三是实验部分的内存占用、吞吐和五个基准上的质量差距，注意区分“平均差几个点”在不同任务上的分布。代码和 checkpoint 已开源，建议实际跑一遍 8B 档位，观察 SSD 读取与计算重叠的实际效果。
  - 优先级依据：直接命中 MoE 推理的内存墙与 offload 调度这一工程核心问题，方法可复现且开源，对想做大模型推理部署的学习者当天就值得精读。

- [P0] [Fathom: Per-Query Read Depth for Sparse Decoding over Offloaded KV Caches](https://huggingface.co/papers/2609.17652)（Hugging Face Daily Papers · 论文 · 推理部署与性能优化 · 新 · 2026-09-17 · Vivek Kalyanarangan）
  - 中文摘要：这篇论文提出 Fathom，针对 agentic 长会话场景下 KV cache 被 offload 到主机内存时的稀疏解码问题。当会话达到百万 token 且多会话常驻时，KV cache 和用于排序的索引都在 host memory，为 top-k 步骤扫描全部 n 个 key 成为解码瓶颈。Fathom 让每个 query 自行决定读取每个 key 通道的多少比特：4-bit K cache 按通道主序存成 bit planes，读取前 t 个 plane 就等价于该通道的 t-bit 量化器，query 根据通道的方差加权重要性做反向注水来分配比特预算。在 Qwen3-8B 百万 token 设置下，单步解码 GPU 时间比 Double Sparsity、Loki、SparQ r=32 的 136-bit 扫描快 1.67 倍，在与 SparQ 68-bit 读取相同的 GPU 时间内少读 18% 字节且七个设置中六个注意力误差更低；RULER 类任务上每个 per-token 扫描都匹配精确 top-k 解码，真实 coding agent 会话中以 92 bit 达到最准
  - 亮点：把 4-bit K cache 按通道存成 bit planes，让每个 query 用反向注水按通道重要性动态决定读取比特数，实现 per-query 读取深度。
  - 注意：方法收益依赖索引位于 host memory 这一前提，索引常驻 GPU 时无加速；bit-plane 布局对现有量化 serving 栈的改动成本需要评估；实验主要围绕 Qwen3-8B 和 RULER/coding agent 场景，泛化性待验证。
  - 学习指引：重点看 bit-plane 存储布局与反向注水比特分配算法的推导，理解为什么“读取前缀 plane 等于低比特量化器”这一性质成立；再看它与 Double Sparsity、Loki、SparQ 的对比实验设置，特别是 GPU 时间与读取字节数两个维度的权衡。注意作者自己指出的局限：当索引常驻 GPU 时该方法不再更快，说明它解决的是特定内存层级下的问题。
  - 优先级依据：长上下文 agent 推理的 KV cache offload 是当前部署热点，方法有清晰的理论动机和可复现的对比实验，值得当天精读。
