- [P0] [Document Retrieval-Aware Chunking (D-RAC): Universal Retrieval-Aware Ingestion of Enterprise Documents via PDF Normalization and Multimodal Markdown Conversion](https://huggingface.co/papers/2609.24220)（Hugging Face Daily Papers · 论文 · RAG 与数据工程 · 新 · 2026-09-22 · Uday Allu, Abhivanth Sivaprakash, Pratik Singh）
  - 中文摘要：这篇论文提出 D-RAC（Document Retrieval-Aware Chunking），把此前面向网页的 W-RAC 框架扩展到企业异构文档。核心思路是先把任意格式（PDF、Word、PPT、扫描件）统一归一化为 PDF，再用一次多模态 LLM 把渲染页面转成检索友好的 Markdown（表格改写为自包含的陈述句、保留标题层级），之后按 W-RAC 的方式做确定性解析成可 ID 寻址的单元，并让轻量 LLM 只在标识符层面做 chunk planning，而不重新生成原文，从而在保留阅读顺序和表格语义的同时控制成本与幻觉风险。
  - 亮点：用“先归一化为 PDF、再单次多模态转换、最后只在 ID 上做 chunk planning”的三段式设计，把文档解析的保真度和 LLM 成本解耦。
  - 注意：把任意格式先转成 PDF 会引入一次有损转换，扫描件和复杂版式的还原质量高度依赖上游 PDF 渲染；多模态 LLM 改写表格为 prose 也可能改变原始数值语义，需要人工抽检。
  - 学习指引：重点看三处：一是 PDF 归一化这一步为什么能覆盖几乎所有格式，以及它带来的保真度代价；二是多模态 LLM 把表格改写成 prose 的 prompt 设计与失败案例；三是 ID-addressable 单元加 identifier-level chunk planning 的工程实现，理解它如何避免在 chunking 阶段重新生成文本。实验部分要关注与规则抽取、OCR、纯 agentic chunking 的对比指标和 token 成本。
  - 优先级依据：RAG 数据工程是大模型算法工程师的高频落地场景，该文给出了可直接借鉴的 ingestion 流水线设计，属于当天值得精读的 P0。

- [P0] [onPanda: Efficient Annotation of On-Policy Alignment Data for LLMs and Agents via Token-Level Correction](https://huggingface.co/papers/2609.24983)（Hugging Face Daily Papers · 论文 · 后训练与对齐 · 新 · 2026-09-22 · Lei Yang, Mengyin Liu, Jia Wang）
  - 中文摘要：这篇论文介绍 onPanda，一个用于高效标注 LLM 对齐数据和 agent 轨迹的交互工具。它采用 token 级纠正作为核心交互：标注者读到第一个不合适的 token 时，从模型候选 token 中选替代或自由输入正确文本，系统截断该位置之后的内容并从修正后的前缀继续生成，循环“定位—纠正—继续”直到满意。小规模对照研究显示中位标注时间比人工后编辑减少 52%，且最终回复绝大多数 token 仍由模型生成，因此数据较好地保留模型采样分布，适合构造 on-policy SFT 和偏好数据；同时 token 级纠正天然提供带精确位置的正负样本对。
  - 亮点：把标注动作从“重写整段回复”变成“定位第一个错误 token 并继续生成”，在保留模型采样分布的同时把标注成本大幅压低。
  - 注意：标注时间减少 52% 来自小规模受控研究，统计功效有限；token 级纠正依赖标注者能准确定位“第一个不合适 token”，对复杂推理或长程 agent 轨迹可能不适用。
  - 学习指引：重点看交互机制如何保证 on-policy 性质（截断后继续生成而非人工重写），以及 token 级纠正如何转成 SFT 和偏好数据的正负样本对。关注其小规模用户研究的实验设计、标注时间统计口径和样本量，判断结论的可推广性。工具与外部环境/工具的连接部分也值得看，理解 agent 轨迹标注的工程细节。
  - 优先级依据：对齐数据构造是后训练环节的核心工程能力，该工具提供了可复用的 on-policy 数据生产范式，值得当天重点了解。
- [P0] [RBS-Attention: Radius-Bounded Sparse Prefill for Long-Context Large Language Models](https://arxiv.org/abs/2609.20971)（arXiv cs.AI · 论文 · 推理部署与性能优化 · 新 · 2026-09-22）
  - 中文摘要：这篇论文针对长上下文 LLM 推理中 prefill 阶段 dense self-attention 开销过大的问题，提出免训练的稀疏 prefill 方法 RBS-Attention。作者指出仅用 block 质心做稀疏选择会因“mean dilution”漏掉块内高相关 token，于是设计两个互补分支：质心基分支捕捉平均相关性，rescue 分支利用最大 key-block radius 及其随 prompt、层、头变化的分布识别可能被低估的块，两分支独立阈值化后合并 mask，同时保持规则的 block-sparse FlashAttention 执行。在 H100 上，Qwen3-30B-A3B 在 128K 下取得 20.65 倍独立 prefill attention 加速、11.92 倍 vLLM prefill attention 加速和 5.97 倍端到端 TTFT 加速，dense Qwen3-32B 上 RULER 总体准确率 88.65 对 dense 的 89.52。
  - 亮点：用“质心 + 最大半径 rescue”双分支稀疏选择，在不训练的前提下同时拿到显著 prefill 加速和接近 dense 的长上下文精度。
  - 注意：加速数据集中在 H100 和特定模型（Qwen3 系列），换硬件、换模型或换 attention 实现后收益可能变化；RULER 上仍有约 0.9 个点的精度差距，且 rescue 分支的阈值需要调参。
  - 学习指引：重点看 mean dilution 问题的定义与可视化证据、rescue 分支中 radius 分布如何按 prompt/layer/head 估计，以及两分支 mask 合并后如何仍能走 FlashAttention 的 block-sparse 路径。实验部分关注加速比是在什么 batch/长度/硬件配置下测得，以及 RULER 等长上下文评测上的精度损失是否可接受。
  - 优先级依据：长上下文 prefill 优化是推理部署的高价值方向，该文方法免训练、可直接接入 vLLM，属于当天值得重点看的 P0。
